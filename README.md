# 鱼力max · 掉线补回

> **鱼力max 系列（鱼有分寸）**：[活人感](https://github.com/Vegra85/astrbot_plugin_fatfish_alive) · [认 AI](https://github.com/Vegra85/astrbot_plugin_fatfish_aiguard) · [看图懂梗](https://github.com/Vegra85/astrbot_plugin_fatfish_seememe) · [法庭](https://github.com/Vegra85/astrbot_plugin_fatfish_court) · [掉线补回](https://github.com/Vegra85/astrbot_plugin_fatfish_catchup) —— 每个都能单独用，一起装自动让路。作者 Vegra85；跟市场上其他叫「大肥鱼」的插件无关。

一句话：AstrBot 重启、QQ（NapCat）掉线、模型出错的那段时间，别人私聊它、群里 @ 它的话就石沉大海 —— 对方以为它不理人。装上以后，恢复了它自己去翻聊天记录，把冲它说的、还没回的按对话补回一次（群里回的时候 @ 那个人）；太久以前的、补过的、它后来回过的、别人家 AI 发的都不补。

## 30 秒装好

1. 插件市场搜「鱼力max」或「掉线补回」→ 装 → 重启 AstrBot
2. 默认配置就能用；最常改的几项：
   - 「最长补多久以前的」（默认 120 分钟）
   - 「模型出错没回上的也补」（默认开）
   - 「它的名字 / 外号」（群里只叫名字、没 @ 的也算找它）
3. 哪里看效果：
   - 发 `/补回`：最近一次掉线多久、补了哪些对话、哪些没补、为什么
   - AstrBot 管理员发 `/补回 现在`：手动补一次
   - AstrBot 面板 → 插件 → 掉线补回 → 打开页面：最近 20 次掉线、补了谁、模型出错还没补的
   - 日志里搜 `[掉线补回]`

装上以后才开始记（第一次装上那次重启不补：那之前它没记「哪些消息收到过」，分不清哪些是故意没回的）。

## 什么算「掉线」

| 哪种 | 怎么认出来 | 补什么 |
|---|---|---|
| AstrBot 重启 / 崩了 | 插件每 30 秒记一次心跳；开机时跟上次的心跳比，中间空了多久就是掉线的那段。上次没正常关（崩了 / 被直接杀掉）或者中间空了 90 秒以上才算；改配置热重载、秒重启不算 | QQ 连上以后等几秒，翻那段时间的聊天记录 |
| NapCat 断开又连上（AstrBot 没重启） | AstrBot 的适配器自己不发「连上了」的事件，插件挂在它底下收 NapCat 的元事件：重新连上 / 心跳隔了一大截 | 连上以后翻断开那段的聊天记录 |
| 模型出错（欠费、限流、接口挂了） | 找它的这一轮模型报错、什么都没回（自己记；装了活人感、它的兜底把报错拦下了也认得出） | 按会话等：这个会话（这个群 / 这个人的私聊）回上了一句，补这个会话里出错时没回上的；他本人又来找它，之前没回上的那几条并进那一轮一起回。别的会话正常不算这个会话好了 |

## 补的规矩（别补错）

- **只补冲着它说的**：私聊都算；群里只算 @ 它、引用它、叫它名字的，和他紧跟着（2 分钟内）补充的几句。群里别人之间聊天不补，@ 全体不算。
- **每个对话合成一次**：私聊 = 那个人；群里 = 找过它的那个人（三个人 @ 了它就是三个对话，各回各的）。一个对话最多带最近 5 条（@ 它的那句一定带上）。
- **太久以前的不补**（默认 2 小时）；一次最多补 10 个对话；对话之间隔 5 秒。
- **在线时收到过的不补**：收到过 = 当时处理过 —— 回了，或者被别的插件故意拦了（比如群管让它安静、认 AI 刹车）。例外：收到了但没回上的（重启打断的、模型出错的）照补。
- **它后来已经回过的不补**：私聊里它后来说过话；群里它后来 @ 了他、引用了他，或者没 @ 谁但他是最后一个找它的。
- **补过的记下来不重复补**；同一条最多补两次（补的时候模型又出错了，等好了再补一次，再不行就算了）。同一条消息只补一次：聊天记录和「模型出错没回上」两条路都捡到了也只进一个对话。
- **指令不补、不拼**：以唤醒前缀开头的（默认「/」：「/reset」「/new」），和一开头就是 AstrBot 认的指令名的（补回的那条 @ 着它 / 是私聊，不带「/」也会被当成指令）—— 拼成「/reset\n在吗」交回 AstrBot 会被当成指令执行。
- **只提到它的 QQ 昵称不算找它**（默认）：「机器人又挂了」这种不补；只认配置里写的名字 / 外号。想让昵称也算，开「QQ 昵称也算「叫它名字」」。
- **别人家的 AI 发的不补**（问鱼力max · 认 AI）。
- 补的时候这期间它已经回过他了（他又发了一句、它回了），补的那句就不发了。

交给模型的时候，这一轮带一段事实（临时段，不进对话记录）：

```
# 补回（系统记录，不是谁说的话）
下面这 2 条是「阿木」私聊里发给你的，那时候你这边掉线了（重启），没收到、没回：
- 13:40（20 分钟前）「在吗」
- 13:41（19 分钟前）「帮我看个东西[图片]」
你掉线的那段：13:35 到 13:58（23 分钟）。
现在是 14:00。
```

他打的原话压成一行、用「」包着：原话里的换行、他手打的「# 补回」「- …」不会变成新的标题、新的一条。

模型出错没回上、他本人又来找它的时候，之前那几条并进他这一轮（同样是临时段）：

```
# 补回（系统记录，不是谁说的话）
「阿木」这一条之前还发过 2 条，那时候你这边出了错，没回上：
- 13:52（8 分钟前）「在吗」
- 13:53（7 分钟前）「帮我查个东西」
现在是 14:00。
```

怎么接、要不要解释、怎么说，由模型自己定（插件不写台词）。

## 和哪些插件能一起装

| 插件 | 一起装会怎样 |
|---|---|
| 鱼力max · 认 AI | 别人家的 AI 发的不补（问它的公开方法 `is_bot`）。 |
| 鱼力max · 群管说了算 | 补群里的之前先问它（`may_speak`）：那个群在静音、被禁言 → 先不补（日志写着原因）；在安静 → 照补（补回本来就是回 @ 它的）。补回的那条也照样过它的拦。 |
| 鱼力max · 活人感 | 模型出错时活人感的兜底会把报错拦下（私聊换成一句「（系统提示）这会儿连不上模型……」，群里不发）—— 本插件排在它前面，照样记成没回上；那句系统提示不算「回过他」，这个会话好了以后照补。活人感的兜底记录只认带着同一个会话的（它现在的记录不带会话，等于不用 —— 靠的是本插件自己逐条看到的报错 / 空回复），不会把别的会话的报错算到这一轮。补回的那条会经过活人感（攒一攒、发消息都照常）。 |
| 天使之心 angel_heart | 补的那句因为「这期间已经回过他了」不发的时候，替它把那一轮记成结束。 |
| AstrBot 的「引用回复」「回复时 @」 | 开着「回复时 @」：AstrBot 自己 @，本插件不重复加；开着「引用回复」：引用他最后那条。 |

## 常见问题

1. **重启以后它把一堆旧消息都回了一遍？** 不会：在线时收到过的、它回过的、补过的都不补，太久以前的也不补。日志里每次补完都有一行「补了谁；没补：原因 N 条」。
2. **群里有人 @ 它，重启以后没补？** 先看 `/补回` 的「没补」：太久以前、它后来回过了、群管说了算（在静音）、别人家的 AI……；另外要 NapCat 的聊天记录接口能用（见已知限制）。
3. **模型挂了半天，好了以后补了好多？** 只补找它的、没回上的，一次最多 10 个对话、每个最多 5 条；不想补模型出错的，关掉「模型出错没回上的也补」（关了就不记、不补，重启和手动补也不补）。
4. **模型出错的，什么时候补？** 按会话：这个群里有人找它、它回上了，就补这个群里没回上的（@ 着各自的人）；私聊里他本人再来找它，之前没回上的并进那一轮。别的群、别的私聊正常不算 —— 不然一个会话一直挂（比如这个会话的对话记录太长、被内容审核拦），每条都会再试一遍、往群里再发一遍报错。私聊里他一直没再来的，可以 `/补回 现在` 手动补。
5. **会不会补到一半它自己又说一遍？** 补的时候它已经回过这个人了，补的那句不发。
6. **第一次装上为什么不补？** 那之前插件没记「哪些消息收到过」，分不清哪些是故意没回的（比如被别的插件拦了），所以从装上开始算。
7. **改了配置，它把刚才的消息又补了一遍？** 不会：改配置是热重载（上次正常关、中间只空了几秒），不跑开机补回，日志写着「不跑开机补回」。

## 工作原理

- **钩子**：每条消息（记「收到过」—— 只记找它的那些）；回话请求（记「正在等模型回」；补回的那一轮加那段事实；他之前模型出错没回上的几条并进这一轮）；模型回完（报错 / 什么都没回 → 没回上；回上了 → 这个会话好了）；发送前（框架把报错发出来了 → 没回上，排在活人感兜底前面；补回的那一轮：群里 @ 他、这期间回过他就不发）；发完（这个对话它回上了，并进来的几条算补过）。
- **并进那一轮的几条先占着**：这一轮回上了算补过；又没回上 / 被别的插件拦了 / 10 分钟没结果 → 放回去等下次。占着的时候，会话好了的那次补回、手动补、翻聊天记录都不会再补一遍。
- **心跳和存档**：存在 `data/plugin_data/astrbot_plugin_fatfish_catchup/state.json`，最多 3 秒存一次（AstrBot 被直接关掉时不会调插件的 terminate，所以勤存）；开机时往前多看 60 秒。上次关掉时正在等模型回的那几轮，这次算「被打断的」，照补。
- **翻聊天记录**：`get_recent_contact` 看哪些对话在那段时间有新消息（问不到就用自己记的「哪些对话有人说过话」）→ `get_friend_msg_history` / `get_group_msg_history` 从最新往回翻（每个对话最多 3 页）。
- **补**：每个对话合成一条「他刚发来的消息」（群里带上 @ 它），交给 AstrBot 正常走一遍：人设、对话记录、别的插件的钩子、群管说了算的拦都照常。消息 id 用他最后那条的，开着「引用回复」时引用的就是那条。
- 判断逻辑在 `core/`（不依赖 AstrBot，可以单独测）：`pick.py` 挑要补的，`track.py` 记账，`notes.py` 写给模型和管理员的字。

## 已知限制

- 要 NapCat 的 `get_friend_msg_history` / `get_group_msg_history`（NapCat 都有；别的 OneBot 实现不一定有）。拿不到聊天记录时，重启 / 断线那段补不了（日志会写），模型出错的照补（那个是自己记的）。
- 认 NapCat 断开又连上靠它的元事件（连上了 / 心跳，NapCat 默认都发）；两样都关掉了的话，只有 AstrBot 重启那种认得出来。
- 只补文字：图、表情、语音写成「[图片]」「[表情]」「[语音]」交给模型，图本身不再下载给模型看。
- 每个对话最多翻 3 页聊天记录（私聊 3×30 条、群 3×50 条）；特别热闹的群掉线很久，更早的 @ 可能翻不到。
- 「它后来回过了」按聊天记录里它说的话算：群里它没 @ 谁、没引用谁的一句，算回的是在它之前最后一个找它的人。
- 群里只叫它名字（没 @）的，要在配置里填上它的外号才认得；QQ 昵称默认不算（开「QQ 昵称也算」才算）。
- 模型出错按会话等「这个会话回上了一句」：这个会话一直没人找它（私聊里他没再来）就一直不补（可以 `/补回 现在` 手动补）。
- 唤醒前缀开头的一律当指令不补（AstrBot 唤醒前缀配了别的词，比如「小鱼」，以它开头的掉线消息也不补）。
- 第一次装上之前的消息不补；`/补回 现在` 也只看装上以后的。
- 只支持 QQ（aiocqhttp / NapCat），AstrBot ≥ 4.29。
